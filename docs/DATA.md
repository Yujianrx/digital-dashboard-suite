# 数据与部署

## 主机存储

`server/dashboard-host.ps1` 提供静态页面、`GET /api/storage`、`GET /api/revision` 和带版本检查的 `POST /api/storage`。数据保存在当前项目下，只有全空数据库才读取 `initial-state.json`。首次模板中的活动来源没有任何日期数据。

导入数据和新建活动沿用页面入口。备份包含自己的业务信息，仅保存在本机，不应提交到 Git。

## 指标口径

券活动使用领取张数、核销张数及去重后的连带消费金额；商品活动使用销量、销售金额和预计收入；储值使用订单单数和实付充值金额。人数与曝光没有来源就保持未配置。订单、商品和券的业务编号应按自己的系统核实。

来源类型登记在 `member/business-scopes.js` 中；默认的两个来源与空模板一一对应。若增加商品/券来源，按实际活动编号登记 `kind: 'product'` 或 `kind: 'coupon'`，并填入经过确认的编号集合。前端每日汇总不能凭空按商品或充值方案拆分。

## 可选经营大屏接口

没有数据源时使用大屏的“空数据模板”。需要真实数据时，在 `operations/` 下根据 `.env.example` 创建自己的 `.env.local`，按 [接入文档](../operations/docs/DATA-INTEGRATION.md) 调整 SQL 和字段映射。不要复用其他企业的标识和过滤条件。

例如将自有 API 启动在空闲的本机端口，然后显式配置套件代理：

```powershell
# 第一个终端，自己的大屏数据服务
$env:API_PORT='18787'
cd operations
npm run dev:api

# 第二个终端，套件根目录
$env:DASHBOARD_OPERATIONS_API='http://127.0.0.1:18787'
npm start
```

代理默认禁用，不自动启动或探测其他已有服务，只接受显式配置的本机只读接口。每日快照使用自己的配置，接口错误时保留上一次成功快照。

主机服务默认仅允许本机访问，不含公网账号系统。若需要多用户联网部署，请在自己的受控环境中配置认证、访问范围、备份和服务运行方式；不要直接把主机端口暴露到公网。
