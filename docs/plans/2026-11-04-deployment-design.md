# 本地、网站与静态部署设计

本方案已由项目维护者确认实施。保留现有业务功能、指标口径、活动编号关联及空数据发布约束。

## 运行方式

- 本地：Node.js 22.13+，默认仅监听 127.0.0.1:8765，SQLite 保存、备份和版本冲突检查。兼容原 SQLite 表结构；Windows PowerShell 入口保留为兼容入口。
- 网站：同一 Node.js 服务，单管理员密码登录、HttpOnly 会话 Cookie、同源写入检查、登录限流；提供 Docker、持久化卷和 HTTPS 反向代理配置。首次为空数据。凭据仅通过部署环境设置。
- 静态：独立构建目录，明确配置 browser 存储；浏览器数据按站点路径隔离，不访问存储 API。默认空数据，提供 JSON 备份导入导出；明确标注仅保存在当前浏览器。支持 GitHub Pages 子路径。

## 数据和故障

所有模式使用现有 JSON 数据结构、相同指标计算和活动编号。服务器失败不自动降级到浏览器存储。保存失败保留页面待保存内容，冲突继续检测。首次初始化不覆盖已有记录，清空后重启不重新注入模板。静态构建只复制发布资源及经过检查的空模板，不复制数据库、环境文件、备份或日志。经营数据代理默认关闭，只接受显式配置的本机只读接口。

## 架构与验证

服务端分为配置、SQLite 存储、认证、HTTP 路由；前端通过运行配置选择存储模式，并用部署根路径解析接口。经营大屏使用相对资源地址，静态模式禁用依赖服务器的入口。验证包括原有业务测试、持久化重启、并发冲突、请求校验、认证、静态路径隔离、构建、类型检查和隐私扫描；CI 覆盖 Windows、Linux 和 macOS。部署支持单服务实例，不提供多租户或横向扩容。
